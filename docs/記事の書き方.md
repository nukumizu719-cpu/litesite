# 予想記事の書き方

## 全体の流れ

1. 出馬表とオッズを確認する
2. Claude に分析を依頼する（下のプロンプトを使う）
3. 出力された Markdown を `src/content/races/{年}/{MMDD}-{レース名}.md` に保存する
4. `git add` → `git commit` → `git push` すると、GitHub Actions が2分ほどで本番へ反映する
5. レース後、同じファイルに `result:` ブロックを追記して再度 push する

所要時間の目安は、予想1本で20分・結果追記で5分。

---

## 実購入後の記事化（買い目・結果からの提出フォーマット）

事前予想をClaudeに立てさせるのではなく、**実際に購入した買い目と結果だけを渡して記事化する**場合は、以下のフォーマットで貼り付ける。

```
【レース】2026/○/○ ○○競馬場 ○R ○○ステークス

【購入記録】※JRA投票照会CSVから転記
| 券種 | 買い目 | 点数 | 1点あたり | 投資 | 払戻 |
|---|---|---|---|---|---|
| ワイド | 3-6-7 BOX | 3 | 300円 | 900円 | 2,250円 |
| ... |

【結果】1着○番○○／2着○番○○／3着○番○○

【印と評価】
| 馬番 | 馬名 | 印 | 人気 | オッズ | 減点根拠 |
|---|---|---|---|---|---|
| ... |

【この記事で書きたいこと】
（例: 紐を厚く取った判断が結果につながった／軸が飛んで全滅した原因）
```

Claude Code はこの提出を受け取ったら、以下の手順で処理する。

1. **CLAUDE.mdの絶対原則1を最優先する。** プレースホルダー（○○、○番、「...」など）が残っている、数字に矛盾がある、購入記録の裏付けが取れない場合は記事化せず、必ずユーザーに確認する
2. `src/content.config.ts` のスキーマに沿って frontmatter を組み立てる（marks / bets / result / budget / tags）。買い目テーブルの投資・払戻合計と `budget` / `result.payout` が一致することを確認する
3. 本文は CLAUDE.md の「文体」ルール（一人称不使用、体言止め禁止、負けても同じ熱量）に従い、【この記事で書きたいこと】を軸に構成する
4. `src/content/races/2026/{MMDD}-{レース名のローマ字}.md` に保存する
5. `src/data/ledger.ts` の該当レースの行に `articleId` を設定する（該当行が無ければ台帳側の追加をユーザーに確認する）
6. `npm run build` → `git add -A` → コミット → `git push`（PR作成・マージはユーザーがGitHub上で行う）

## Claude に渡すプロンプト（事前予想を立てさせる場合）

そのままコピーして使えます。`{ }` の部分だけ書き換えてください。

```
{レース名}（{開催日} / {競馬場}・{芝orダート}{距離}m / {頭数}頭 / {ハンデ戦かどうか}）の予想をお願いします。

私のロジックを適用してください：

【人気馬チェックリスト（減点方式・減点が最も少ない人気馬を軸候補にする）】
-5点：前走逃げて好走 / 初ダートまたは初芝 / 距離延長ローテ / ダートで前走牝馬限定戦
-4点：昇級初戦 / 前走が特殊条件 / 前走ローカル場
-3点：半年以上の休み明け / 芝の外枠かダートの内枠 / トップハンデの斤量
-2点：急坂コースで好走なし / 馬体重±15kg以上変動
-1点：右回り左回りで好走なし / 冬の牝馬か夏の牡馬

【危険な人気馬の判定基準】
前走逃げた馬 / 半年以上の休み明けで上位人気 / 特殊条件で勝った馬 /
芝の外枠替わりまたはダートの内枠替わり / 牝馬限定戦の人気馬が混合戦（ダート）に出走

【馬券購入ロジック】
・ワイドを起点に組み立てる。4〜6番人気かつ6〜10倍を起点にし、1〜2番人気と組む
・人気馬同士のワイドボックスは買わない
・選んだ組み合わせと同じ相手の馬連も2〜3点に絞って追加する。単勝1倍台が本命のレースでは馬連を買わない
・単勝は4.0〜9.9倍のゾーンから、前走4〜6着・条件好転・逃げ先行の馬を狙う
・複勝は基本買わない
・3連複は荒れそうなレース（人気馬に不安要素／ハンデ戦／牝馬限定重賞／2歳戦／穴馬候補多数）限定。20点以内、軸は人気馬から選ぶ。紐は薄くせず厚めに取る
・3連単と枠連は限定的に使用
・フォーメーションの1列目は最低2頭、軸馬は全列に入れる、点数は購入前に検算する、大穴への厚張りはしない

【投資額】
{9,000}円

【出力形式】
下のテンプレートの通り、frontmatter 付きの Markdown を丸ごと出力してください。
そのままファイルに貼れる形にしてください。
ロジックで結論が出せない場合は、理由を説明したうえでその旨を伝えてください。
```

```markdown
## 展開想定

本文はここから。印・減点表・買い目テーブルは frontmatter から自動で組み上がるので、
本文には表に書けないことだけを書く。
```

### YAML で気をつけること

- `summary` や `note` に **コロン（`:`）を含めるときは必ず `"` で囲む**。囲まないとパースエラーになる
- `mark` の記号（`◎` など）は `"◎"` のようにクォートで囲む
- `hits` は的中した券種の配列。全部外れたら `hits: []` にして `payout: 0` にする
- `result` ブロックは、レース前は**存在しないこと**が正しい状態。空で置いておくとエラーになる

---

## 券種の書き方

| type | combo の例 | 意味 |
|---|---|---|
| 単勝 | `"11"` | 11番の単勝 |
| ワイド | `"5-11"` | 5番と11番 |
| 馬連 | `"5-11"` | 5番と11番 |
| 3連複 | `"5-11-2,14"` | 5・11軸から2番と14番へ |
| 3連単 | `"5→11→2,14"` | 矢印で着順を表す |

`combo` の文字列はそのまま表示され、コピーボタンのテキストにも使われます。
読み手が投票サイトに写せる形にしてください。

## 動作確認

```bash
npm run dev      # http://localhost:4321 で確認
npm run build    # 本番と同じビルドを通す
```

`npm run build` が通れば、frontmatter のスキーマ違反はありません。
逆にスキーマに合っていないとビルドが落ちるので、push 前に一度通しておくと安全です。
